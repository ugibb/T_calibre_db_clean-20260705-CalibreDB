# Calibre 文库清洗工具重构方案

**文档版本**: v1.0  
**创建日期**: 2026-10-01  
**目标**: 提供一站式、可验证、易执行的完整解决方案

---

## 一、当前痛点分析

### 1.1 执行流程复杂
- **问题**: 需要手动执行 Step1 → Step2 → Step3 → Step4 → Step5，每步都需要单独命令
- **影响**: 容易遗漏步骤，执行顺序错误，参数配置繁琐
- **示例**: 
  ```bash
  # 需要记住5个不同的命令和参数
  python cli.py step1 --batch 2026-09-24
  python cli.py step2 scan --batch 2026-09-24
  python cli.py step3 --batch 2026-09-24
  python cli.py step4 sql --batch 2026-09-24
  python cli.py step5 scan --batch 2026-09-24
  ```

### 1.2 验证过程繁琐
- **问题**: 需要手动编写和运行多个验证脚本（4层验证）
- **影响**: 验证耗时，容易遗漏关键检查点
- **当前验证**:
  - Layer 1: 数据库完整性（orphan records）
  - Layer 2: 删除正确性（CSV vs SQL vs DB）
  - Layer 3: 数据一致性（merged vs cleaned）
  - Layer 4: 物理文件一致性

### 1.3 BAT 执行问题
- **问题**: 
  - BAT 脚本执行速度慢（管道阻塞问题）
  - 无法实时监控进度
  - 失败后难以恢复
- **影响**: 7,430 本书需要数小时，中途失败难以追踪

### 1.4 状态追踪困难
- **问题**: 无法清晰了解当前执行到哪一步，每步的结果是什么
- **影响**: 需要手动检查输出文件，对比数据库记录数

### 1.5 配置分散
- **问题**: 配置分散在多个 JSON 文件中（pipeline_config.json, step1_rules.json, step2_config.json）
- **影响**: 修改配置需要编辑多个文件，容易出错

---

## 二、重构目标

### 2.1 核心目标
1. **一键执行**: 单条命令完成整个清洗流程
2. **自动验证**: 每步执行后自动验证，确保正确性
3. **进度可视**: 实时显示执行进度和中间结果
4. **错误恢复**: 支持断点续执行和回滚
5. **简化配置**: 统一配置管理

### 2.2 非目标
- 不改变核心清洗逻辑（Step1-5 的算法保持不变）
- 不迁移到新的编程语言（继续使用 Python）
- 不改变输出文件格式（保持向后兼容）

### 4.2 进度显示

```python
class ProgressDisplay:
    """进度显示"""
    
    def __init__(self, total_steps: int):
        self.total_steps = total_steps
        self.current_step = 0
        
    def start_step(self, step_name: str, description: str):
        """开始步骤"""
        self.current_step += 1
        print(f"\n[{self.current_step}/{self.total_steps}] {step_name}: {description}")
        
    def update_progress(self, current: int, total: int, speed: float = None):
        """更新进度"""
        percent = current / total * 100
        bar = self._create_progress_bar(percent)
        
        msg = f"  {bar} {percent:.0f}% ({current}/{total})"
        if speed:
            remaining = (total - current) / speed
            msg += f" 预计剩余: {remaining:.0f} min"
        
        print(msg, end='\r')
        
    def complete_step(self, duration: float):
        """完成步骤"""
        print(f" ✓ 耗时: {duration:.1f}s")
        
    def _create_progress_bar(self, percent: float, width: int = 40) -> str:
        """创建进度条"""
        filled = int(width * percent / 100)
        bar = '━' * filled + '○' * (width - filled)
        return f"[{bar}]"
```

## 八、Step1-4 设计与核心目标的对齐分析

### 8.0 工具的初衷

**核心目标**: 自动化清理重复的 book + data 记录，同时清理电子书库中的重复电子书文件，优化磁盘存储空间。

**关键指标**:
1. **去重准确性**: 准确识别并删除重复记录，不误删有效数据
2. **磁盘释放**: 最大化释放重复文件占用的磁盘空间
3. **数据安全**: 确保清理过程可回滚，不丢失用户数据
4. **执行效率**: 快速完成清理，减少人工干预

### 8.1 当前设计如何服务核心目标

#### Step1: 去重（直接服务核心目标）
**职责**: 删除重复的 book + data 记录
- 使用 `normalize_title(title) + bytes + initPath` 作为去重键
- 保留 `data_id` 最小的记录，删除其他重复项
- 输出：去重后的数据库 + 去重报告 CSV

**对核心目标的贡献**:
- ✓ 直接减少数据库中的重复记录
- ✓ 为后续物理文件清理提供准确的删除清单
- ✓ 通过 `initPath`（来自 Windows 文件系统）提高去重准确性

**当前问题**: 无，设计合理

#### Step2: 编码修复（间接服务核心目标）
**职责**: 修复 GBK/CP936 编码乱码问题
- 扫描 12 个字段的编码问题
- 删除无法修复的乱码记录（原始字节已丢失）
- 修复可恢复的记录（通过 BookInitPath）

**对核心目标的贡献**:
- ✓ 清理不可信的乱码记录，避免后续误判
- ✓ 修复可恢复的记录，保留有效数据
- ✓ 提高后续去重和清理的准确性

**当前问题**: 无，设计合理

#### Step3: 回归过滤（直接服务核心目标）
**职责**: 根据规则过滤无效记录
- 删除垃圾标题（含特定关键词）
- 删除非目标格式（非 epub/mobi/azw3 等）
- 删除 Unknown 作者/标题的记录

**对核心目标的贡献**:
- ✓ 进一步清理无效记录，释放更多磁盘空间
- ✓ 通过规则配置，灵活适应不同用户的需求
- ✓ 输出清洗后的数据库，为物理文件操作做准备

**当前问题**:
- ⚠️ **功能重叠**: Step3 内部已执行 SQL 并生成 `metadata.cleaned.db`
- ⚠️ **职责不清**: Step3 同时承担了"生成候选列表"和"执行清洗"两个职责
- ⚠️ **与 Step4 重复**: Step4 的 `sql` 和 `apply` 子命令在重复 Step3 的工作

**优化建议**:
```
Step3 应该只做一件事：根据规则生成待删除候选列表（CSV）
不执行 SQL，不生成 cleaned.db
让用户确认候选列表后，由 Step4 统一执行
```

#### Step4: 清洗执行（直接服务核心目标）
**职责**: 执行数据库清洗 + 物理文件操作
- 生成清洗 SQL（基于 Step1-3 的确认 CSV）
- 执行 SQL 生成清洗后的数据库
- 生成物理文件操作 BAT（移动重复文件到隔离区）
- 验证清洗结果

**对核心目标的贡献**:
- ✓ 真正执行数据库清洗，删除重复记录
- ✓ 生成物理文件操作指令，释放磁盘空间
- ✓ 提供验证机制，确保清洗正确性

**当前问题**:
- ⚠️ **过度拆分**: 被拆分为 `sql` / `apply` / `verify` 三个子命令
- ⚠️ **与 Step3 重复**: Step3 已执行 SQL，Step4 apply 是冗余的
- ⚠️ **验证独立**: `verify` 应该自动执行，而非独立命令

**优化建议**:
```
合并为一个统一命令：
python cli.py step4 --batch 2026-09-24

自动执行：
1. 生成 SQL（基于 Step1-3 的确认 CSV）
2. 执行 SQL 生成 cleaned.db
3. 生成物理文件操作 BAT
4. 自动验证清洗结果
```

### 8.2 核心目标导向的优化建议

#### 优化 1: 明确 Step3 与 Step4 的职责边界

**当前问题**:
- Step3 已执行 SQL 并生成 `metadata.cleaned.db`
- Step4 又重复执行 SQL，造成混淆

**优化方案**:
```
Step3: 仅生成候选列表（CSV），不执行 SQL
  输入: Step2 修复后的数据库
  输出: 待删除候选 CSV（系统确认 + 待人工确认）
  职责: 扫描并标记，等待用户确认

Step4: 统一执行清洗
  输入: Step1-3 的确认 CSV
  输出: 清洗后的数据库 + 物理文件操作 BAT
  职责: 执行用户确认的清洗操作
```

#### 优化 3: 物理文件操作优化

**当前问题**:
- BAT 脚本执行速度慢（已修复管道问题）
- 无法实时监控进度
- 失败后难以恢复

**优化方案**:
```python
# 使用 Python 直接执行文件操作（替代 BAT）
def execute_physical_operations(batch: str, output_dir: Path):
    """移动重复文件到隔离区"""
    quarantine_list = load_quarantine_list(batch, output_dir)
    total = len(quarantine_list)
    
    with ProgressDisplay(total) as progress:
        for item in quarantine_list:
            source = LIBRARY_DIR / item.relative_path
            target = QUARANTINE_DIR / item.relative_path
            
            if source.exists():
                target.parent.mkdir(parents=True, exist_ok=True)
                shutil.move(str(source), str(target))
                progress.update(1)
                
                # 清理空目录
                cleanup_empty_parents(source)
```

**对核心目标的贡献**:
- ✓ 直接释放磁盘空间（核心目标的直接体现）
- ✓ 实时显示进度，用户知道何时完成
- ✓ 失败后可从中断处继续，不需要重新开始
- ✓ 消除 BAT 脚本的跨平台问题

#### 优化 4: 磁盘空间释放报告

**当前问题**:
- 用户不清楚清理后释放了多少磁盘空间
- 无法评估清理效果

**优化方案**:
```python
def generate_disk_space_report(batch: str, output_dir: Path) -> DiskSpaceReport:
    """生成磁盘空间释放报告"""
    # 统计隔离的文件大小
    quarantined_size = sum(
        file.size for file in QUARANTINE_DIR.rglob("*") if file.is_file()
    )
    
    # 统计原始数据库大小 vs 清洗后数据库大小
    original_db_size = ORIGINAL_DB.stat().st_size
    cleaned_db_size = CLEANED_DB.stat().st_size
    db_size_saved = original_db_size - cleaned_db_size
    
    # 总释放空间
    total_saved = quarantined_size + db_size_saved
    
    return DiskSpaceReport(
        quarantined_files_size=quarantined_size,
        database_size_saved=db_size_saved,
        total_size_saved=total_saved,
        quarantined_files_count=len(list(QUARANTINE_DIR.rglob("*"))),
    )
```

### 8.5 实施优先级（核心目标导向）
