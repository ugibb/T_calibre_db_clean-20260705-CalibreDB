# 流水线步骤重编号方案

## 背景

当前流水线步骤编号较为混乱（Step00、Step0、Step1-1/1-2/1-3、Step2-1/2-2/2-3），需要重新组织为更清晰的 3 步结构。

## 当前结构

| 当前编号 | 功能 | 输入 | 输出 |
|---------|------|------|------|
| Step00 | 前置去重 | metadata-YYYYMMDD.db | metadata-YYYYMMDD.deduped.db + 3 CSV |
| Step0 | 前置编码修复 | deduped.db | metadata-YYYYMMDD.encoded.db + 3 CSV |
| Step1-1 | 扫描 | encoded.db | step1/ 下 6 个 CSV |
| Step1-2 | 生成清洗指令 | step1/*.csv | step2/step2_cleaning_instructions.{sql,bat} |
| Step1-3 | 执行自清洗 | encoded.db + SQL | step3/metadata.cleaned.db |
| Step2-1 | 比对全量库 | cleaned.db + 全量库 | step4/ 下确认 CSV |
| Step2-validate | 校验填写 | step4/*.csv | 校验报告 |
| Step2-2 | 生成同步指令 | step4/*.csv | step4_merge_instructions.sql |
| Step2-3 | 合并到全量库 | 增量库 + 全量库 | 全量库更新 |

## 新结构（3 步）

### 步骤一：前置预处理（去重 + 垃圾清理）

**功能**：去重（title+bytes+initPath）→ 垃圾标题 → 非目标格式

**输入**：`03-input/metadata-YYYYMMDD.db`

**输出**：`04-output/{batch}/step1/metadata-YYYYMMDD.deduped.db` + 3 个 CSV

**对应原步骤**：Step00

**目录结构**：
```
step1/
├── metadata-YYYYMMDD.deduped.db
├── step1_1_duplicate.csv
├── step1_2_title_junk_keyword.csv
├── step1_3_non_target_format.csv
└── step1_dedup.log
```

**命令**：`./run_calibre.sh 1` 或 `./run_calibre.sh step1`

---

### 步骤二：编码修复 + 自清洗

**功能**：
1. 乱码扫描 + 副本标题扫描 + unknown 扫描
2. 生成自清洗 SQL + BAT
3. 执行清洗

**输入**：`step1/metadata-YYYYMMDD.deduped.db`

**输出**：`step2/metadata-YYYYMMDD.cleaned.db`

**对应原步骤**：Step0 + Step1-1 + Step1-2 + Step1-3

**目录结构**：
```
step2/
├── metadata-YYYYMMDD.cleaned.db
├── step2_1_encode_repair.csv          # 编码修复
├── step2_2_title_copy_repair.csv      # 副本标题修复
├── step2_3_basename_repair.csv        # 文件名修复
├── step2_scan/                        # 扫描产物
│   ├── 2-1-1：系统确认-title命中垃圾关键词.csv
│   ├── 2-1-2：系统确认-重复文件-title_ext_bytes匹配.csv
│   ├── 2-1-3：系统确认-非电子书格式.csv
│   ├── 2-2-1：待人工确认-title乱码.csv
│   ├── 2-2-2：待人工确认-title副本.csv
│   ├── 2-2-4：待人工确认-basename未正确识别.csv
│   └── step2_scan_snapshot.json
├── step2_cleaning_instructions.sql
├── step2_cleaning_instructions.bat
└── step2_execution_report.csv
```

**命令**：
- `./run_calibre.sh 2`        # 全流程（scan→plan→apply）
- `./run_calibre.sh 2 scan`   # 仅扫描
- `./run_calibre.sh 2 plan`   # 生成 SQL/BAT
- `./run_calibre.sh 2 apply`  # 执行清洗

---

### 步骤三：增量合并到全量库

**功能**：比对清洗后的增量库与全量库 → 生成合并指令 → 执行合并

**输入**：`step2/metadata-YYYYMMDD.cleaned.db` + 全量库

**输出**：更新后的全量库

**对应原步骤**：Step2-1 + Step2-validate + Step2-2 + Step2-3

**目录结构**：
```
step3/
├── step3_scan/                    # 比对产物
│   ├── 3 个确认 CSV
│   └── 8 个元数据比对 CSV
├── step3_manual_check_report.csv  # 校验报告
├── step3_merge_instructions.sql   # 合并指令
└── step3_merge_report.csv         # 合并报告
```

**命令**：
- `./run_calibre.sh 3`        # 全流程
- `./run_calibre.sh 3 scan`   # 比对
- `./run_calibre.sh 3 validate` # 校验填写
- `./run_calibre.sh 3 plan`   # 生成合并指令
- `./run_calibre.sh 3 apply`  # 执行合并

## 执行模式

### 模式 1：单步执行（带参数）

```bash
./run_calibre.sh 1   # step1 → 闸口1 → yes → 生成 db → 停止
./run_calibre.sh 2   # step2 scan → 闸口2 → yes → step2 plan → step2 apply → 停止
./run_calibre.sh 3   # step3 scan+plan → 闸口3 → yes → 等待 apply
./run_calibre.sh 3 apply  # 执行合并
```

### 模式 2：全流程执行（无参数）

```bash
./run_calibre.sh   # 自动执行全流程：
                   # step1 → 闸口1(yes) → step2 scan → 闸口2(yes) → step2 plan+apply → step3 scan+plan → 闸口3(yes) → step3 apply
```

**「自动执行」含义**：闸口确认后，自动继续执行下一步，无需手动输入下一条命令。

## 人工闸口（3 个）

| 闸口 | 位置 | 操作 | 确认后执行 |
|-----|------|------|-----------|
| 闸口 1 | step1 完成后 | 确认 3 份 CSV（去重、垃圾标题、非目标格式） | → 自动执行 step2 |
| 闸口 2 | step2 scan 完成后 | 确认编码修复 CSV | → 自动执行 step2 plan+apply |
| 闸口 3 | step3 scan+plan 完成后 | 填写 human_decision + 核对合并指令 | → 自动执行 step3 apply |

**流程图**：
```
step1 → [闸口1] → step2 scan → [闸口2] → step2 plan+apply → step3 scan+plan → [闸口3] → step3 apply
```
